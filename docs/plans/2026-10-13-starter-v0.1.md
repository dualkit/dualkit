# Starter v0.1

13 Oct 2026. Sam chose tokens, Figma and code: one DTCG token file in git feeds Figma variables, CSS and a Tailwind v4 theme, plus eight bilingual React components that mirror. Components are drawn in Figma and approved before any component code.

## Package

`@dualkit/starter` in `packages/starter`, private until the components land. The generated files are committed, so the folder works as a fork-able template as well as a package (`npx degit dualkit/dualkit/packages/starter my-system`). One package rather than a separate template repo keeps the token source, its tests and the site's pipeline demo in one place.

## Token architecture

The source is a DTCG 2025.10 resolver, `tokens/dualkit.resolver.json`, in the same shape as Maidan's, so figma-render imports it with no changes.

- **Primitives:** neutral ramp (cool zinc, no cream), alpha black and white, green and red, a 4px space scale, radii 0, 4, 10 and full, three font families, sizes, weights, line heights and tracking in em.
- **Semantic:** surface, text, border and state colours; inline, stack and inset space; control, media, surface and window radii; motion durations and easings. Components bind these only.
- **Script:** six type roles (display, heading, title, body, label, caption), each with family, size, weight, leading and tracking.
- **Modifiers:** `theme` (light, dark) overrides semantic colours. `script` (en, ar) overrides the type roles: the Arabic face, one size up for display, heading, title and body, more leading, zero tracking and a 14px floor, as the type-pairing skill says. Tests enforce those rules.

## Pipeline

`npm run build -w @dualkit/starter` writes `generated/`:

- `tokens.css`: primitives as values, everything else as `var()` references, under the `--dk-` prefix. Dark mode follows the system and `data-theme`. Arabic type switches on `:lang(ar)`, not on `dir`, and English set inside Arabic gets English type back.
- `theme.css`: a Tailwind v4 `@theme inline` that maps semantic and script tokens only (`bg-surface-ground`, `text-body`, `rounded-control`, `p-inset-control`, `font-heading`). Utilities read the live custom properties, so dark mode and Arabic carry through.
- `figma-variables.json`: Primitives (Value), Semantic (Light, Dark) and Script (en, ar), with aliases kept as aliases. Mode names match what figma-render makes from the same resolver. Easings have no Figma type and are listed as skipped.

To put the variables in Figma, run `figma-render tokens packages/starter/tokens/dualkit.resolver.json`. The JSON is for anyone importing through the Variables REST API or another plugin.

CI rebuilds and fails on any diff in `generated/`, the same way it checks the Cursor rules. A test does the same locally.

## Components to approve in Figma first

Each one has a real bilingual or mirroring problem to solve, which is the reason it is in the set.

1. **Button.** Pill. Directional icons (arrows, chevrons) flip in RTL and the rest do not; padding is logical.
2. **Field.** Label and help follow the page language, while the value takes `dir="auto"`, so an email or IBAN typed into an Arabic form stays left to right.
3. **Digit input.** One-time codes read Arabic-Indic and Persian digits as typed or pasted, and the boxes keep left-to-right order in both languages.
4. **Amount.** AED and SAR through @dualkit/format, currency and number isolated from the sentence around them, tabular digits in both systems.
5. **Date.** Gregorian with Umm al-Qura Hijri beside it, pinned to the Gulf time zone, isolated inside running text.
6. **Tabs.** Order and arrow-key navigation reverse in RTL, and the indicator moves from the inline start.
7. **Sheet.** Opens from the inline end, and swipe to dismiss follows the direction.
8. **Toast.** Stacks from the logical corner, swipes the right way, and isolates mixed-script messages.

Next in line: Phone field (+971, Arabic digits) and a Language switch that flips `lang` and `dir` together.
