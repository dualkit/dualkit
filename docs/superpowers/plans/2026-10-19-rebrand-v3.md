# dualkit.dev v3 home rebrand Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the approved v3 home page (hard edges, ruled frames, smoked glass on the dusk painting, full-viewport sections, the story hero) and the v3 shell (ground, nav with the Products menu, grand footer) on every page of dualkit.dev.

**Architecture:** New home components live in `apps/site/components/v3/`, one file per section, styled by `apps/site/app/v3.css` (tokens and section rules, imported after `globals.css`). Motion logic that can be pure is pure TypeScript in `apps/site/lib/v3/` with Vitest tests; components are thin client wrappers that read those modules and drive WAAPI and one rAF clock. The approved hero prototype is ported, not redesigned.

**Tech Stack:** Next 15.5.27, React 19.1.1, TypeScript 5, Vitest 3, plain CSS, WAAPI, Canvas 2D. No new runtime dependencies.

**Spec:** `docs/plans/2026-10-19-rebrand-design.md` (with `2026-10-19-rebrand-copy.md` and `2026-10-19-rebrand-motion.md` beside it).

## Global Constraints

- Ground `#efece4`, ink `#09090b`, hairline `rgba(0,0,0,.12)`, glass `rgba(11,10,9,.46)` + `backdrop-filter: blur(24px) saturate(140%)` + ring `rgba(255,255,255,.14)`, solid glass button `rgba(255,255,255,.92)`.
- No `border-radius` except seals (50%) and the mascot. No `box-shadow` other than `0 0 0 1px` rings. No `text-transform: uppercase`. No em dashes in any string (`—`).
- Content width 1200 px, page side gutter 120 px at 1440, 16 px at 390. Section spacing 200 px; header to content 80 px; full-viewport sections are 900 px tall at desktop and `min(100svh, 900px)` on phones.
- Display 64 px / 400 / line-height 1.02 / -0.032em; H2 48 / 400 / 1.08 / -0.028em; step 22 / 400 / 1.3 / -0.012em; lede 17 / 1.5; body 15 / 1.5; label 14 / 500; small 13; mono 13.
- Mono stack `'Berkeley Mono', var(--font-plex-mono), monospace`. Never commit or serve Berkeley Mono files.
- Easing tokens (already in `globals.css`): `--ease-expo cubic-bezier(.16,1,.3,1)`, `--ease-ui cubic-bezier(.2,0,0,1)`, `--ease-odo cubic-bezier(.22,1,.36,1)`; add `--ease-move cubic-bezier(.77,0,.175,1)` and `--ease-out cubic-bezier(.23,1,.32,1)`.
- Animate `transform`, `opacity`, `filter` (small text spans only), `clip-path`. Every sequence: runs when 35% in view, pauses off screen and on a hidden tab, and renders its settled state under `prefers-reduced-motion: reduce`. Hover effects only under `(hover: hover) and (pointer: fine)`.
- Every page passes at 1440 and 390: no horizontal scroll (`scrollWidth === innerWidth`), no console errors.
- Copy comes verbatim from `design/figma/gen/v3/copy.mjs`, `sections.mjs`, `menu.mjs`. Counters are real: no number on the page that the code cannot point to.

## Review Focus

1. **Reduced motion:** a visitor with reduced motion must see every section's finished state (fixed Arabic panel, full map, filled bars), never a blank or half-built frame. Each animated section's task adds a test that its `settled()` state is complete.
2. **Arabic rendering:** joined letters, digits in order inside `<bdi>`, RTL alignment, `lang="ar" dir="rtl"` on every Arabic run. Task 2 adds the copy-rules test that every Arabic string in `lib/v3/copy.ts` is wrapped by a component that sets `lang` and `dir`.
3. **Phone width:** the hero camera, the map and the menu at 390 (no clipped pins, no horizontal scroll). The Task 15 verification script asserts it for every section.
4. **Interrupts:** clicking a hero tick, reopening the menu, scrolling away mid-sequence must not jump or leave stuck states. Tasks 5 and 4 test the timeline's `seek()` and the menu's state machine.
5. **Inner pages:** docs, updates, status and bench must still render and read well on the new ground with the new nav and footer. Task 14 screenshots each.

### Task 3: Motion core

**Files:**
- Create: `apps/site/lib/v3/clock.ts`, `lib/v3/spring.ts`, `lib/v3/odometer.ts`, `lib/v3/inview.ts`, `test/v3-motion.test.ts`

**Interfaces:**
- Produces: `createClock(): { now(): number; play(); pause(); seek(ms: number); onTick(fn: (t: number) => void): () => void }`, the single rAF loop for a section; paused clocks do not call `onTick`.
- Produces: `springKeyframes(from: number, to: number, { zeta: number; settleMs: number; fps?: number }): number[]` (values sampled at `fps`, default 60).
- Produces: `odometerColumns(from: string, to: string): { char: string; fromDigit: number | null; toDigit: number | null }[]` (aligns digit columns from the right; non-digits pass through).
- Produces: `useSequence(ref, { threshold = 0.35 }): { visible: boolean; reduced: boolean }` (IntersectionObserver plus `visibilitychange` plus reduced-motion media query).

- [ ] **Step 1: Write the failing tests:**
  - `springKeyframes(0, 100, { zeta: 0.75, settleMs: 550 })`: last value is 100; max value is between 101.5 and 104 (overshoot 1.5 to 4%); the first index within 2% of 100 after which it stays there is `<= 0.6 * 60`.
  - `springKeyframes(0, 100, { zeta: 1, settleMs: 400 })`: never exceeds 100.
  - `odometerColumns('1234.5', '1,234.50')`: returns 8 columns; the last is `{ char: '0', fromDigit: null, toDigit: 0 }`; the `,` column has both digits null.
  - `createClock` with a fake rAF: `seek(1200)` then `now()` is 1200; after `pause()`, advancing the fake rAF does not call `onTick`.
- [ ] **Step 2:** Run, see them fail.
- [ ] **Step 3:** Implement. Spring: damped harmonic oscillator with `omega` solved so the 2% settle time equals `settleMs`.
