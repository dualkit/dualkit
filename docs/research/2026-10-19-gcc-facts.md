# GCC facts for @dualkit/format (checked 19 Oct 2026)

Confidence key: **VERIFIED** = official source read in this session. **SECONDARY** = reputable but unofficial (libphonenumber, OpenPeppol spec pages, MDN BCD, tax-ID guides). **UNCONFIRMED** = no reliable source found.

Example values are built to pass the rule. Phone numbers and IDs with no checksum can still collide with a real person's number, so use them only in tests, never in docs as "a real number".

Details that matter for the validator:
- **Bahrain 6x is split.** 66xxxxxx contains both mobile and fixed sub-ranges (for example, 66300000–66309999 is mobile and 66310000–66329999 is fixed, both Zain). You cannot tell the type from the first two digits. Either return type `unknown` for 6x or carry the ITU range table.
- **Bahrain 3x.** The ITU table lists 320–323, 325, 33–37, 380–384, 387–389 and 39. libphonenumber also accepts 30, 31 and the rest of 38. To avoid rejecting real users, accept any `3XXXXXXX` as mobile.
- **Oman 7x mobile is new.** It was added in the TRA communication of 14 Sep 2025. Old validators that only accept 9x reject real Vodafone (75–77) and Ooredoo (74, 78, 79) numbers.
- **Kuwait 41** is Virgin Mobile, a 2021 addition. A plain `[569]` rule rejects it.

Existing lengths (AE 23, SA 24, BH 22, KW 30, QA 29) and bank-code widths are correct. To add Oman: `OM: { length: 23, bankCode: 3 }`. Optional tightening that is safe per the registry: AE BBAN digits only; BH, KW and QA bank code letters only; SA and OM bank code digits only.

Checksum: ISO 13616 mod-97. Move the first 4 characters to the end, convert letters (A=10 … Z=35), and the number mod 97 must equal 1.

## Do not ship yet

1. UAE mobile 53 and 57. No TDRA allocation (UNCONFIRMED).
2. Bahrain CPR check digit (UNCONFIRMED). Ship length-only, 9 digits, at most.
3. Qatar QID checksum (none known). Oman civil number format (UNCONFIRMED).
4. Saudi ID Luhn, Kuwait Civil ID mod-11 and Emirates ID Luhn are SECONDARY. The EID Luhn already ships. If you keep these, label them "format check" and add a bypass flag so a real ID that fails is never blocked outright.
5. UAE TRN "starts with 1, ends with 03" (SECONDARY, from the e-invoicing spec only). Ship 15-digit length only, and never the "100" prefix.
6. Bahrain VAT 15 digits and Oman VATIN `OM` + 10 digits (SECONDARY). Fine as soft hints, not hard rejects.
7. "No VAT" for Qatar and Kuwait as a hard-coded 0%: model them as `null` (no VAT regime), and re-check each release.
8. Fri–Sat weekends for KSA, KW, BH, QA and OM are SECONDARY. They agree with CLDR, but no government page was read.
9. No trunk prefix and the display grouping for QA, KW, BH and OM (libphonenumber only). Low risk, but not from a regulator.
10. `getWeekInfo` support matrix (MDN BCD): feature-detect rather than assume.
